## Verified findings

1. **[P1] Joining is still two forms rather than details → email confirmation → done.** `index.html:275` contains an email-only form; `index.html:288` contains a second profile form with display name, organization, public visibility, and today's guest result choices. Browser guest join showed only `account-email`; profile was hidden. A synthetic OTP request changed status to “Sign-in link requested. Check your email and open the link in this browser.” A separate signed-in/new-profile fixture showed “Create profile” and opened the second form. `src/app.js:1494` only automatically opens a missing profile if the email dialog is still open; a normal callback navigation may therefore require discovering “Create profile” after returning. The requested one-form journey is not implemented. Collect email/name/organization/visibility/guest-result consent together before verification, preserve the pending details locally, verify the link, save the authorized choices, and show an explicit joined confirmation. This is an observed structure plus source-supported callback inference; no real callback/email was performed. Suggested: `$impeccable onboard`, `$impeccable harden`.

2. **[P1] The primary game input follows all six round cards.** `index.html:238` renders the board before `index.html:247` guess form; `src/app.js:459` always constructs six full round rows, including five locked placeholders. At initial scroll=0 and viewport height 900, `#school-guess` starts at y=2310.875 (320px wide), 2079.875 (390), 1374.719 (768), 1131.406 (1440). Page heights are 2469/2238/1507/1208 respectively. At 320px plus 200% root text, input y=5992.094, page height=6304, still with no horizontal overflow. The player has to pass five non-actionable rounds to answer the first clue, including on desktop. Place the active clue and guess input together before history, and collapse/compact future locked rounds. Suggested: `$impeccable layout`, `$impeccable distill`, `$impeccable adapt`.

3. **[P1] The map is a dense field of 18×18px targets without a list alternative.** `style.css:426` sets `.nc-map-pin` to 18×18; `style.css:1059` deliberately excludes map pins from the ordinary ≥44px rule. The real school data produces 212 pins at 390px. Bounding-box analysis found 1,258 overlapping pairs at initial zoom, including coincident centers; 1,605 pairs have centers <24px apart. Keyboard Enter selects a focused pin and Escape clears it, which is good, but tapping specific schools is difficult and keyboard users must traverse many individual buttons. Cluster overlapping pins, offer a school list/search alternative, and increase effective targets without replacing geographic accuracy. Map spatial arrangement may qualify for WCAG target-size exceptions, so do not label every 18px pin an automatic WCAG failure. Suggested: `$impeccable adapt`, `$impeccable harden`.

4. **[P2] The map stretches North Carolina into a tall shape on phones.** `style.css:307` chooses a 320–520px-tall map independent of width; `src/app.js:759` uses an SVG 100×100 viewBox with `preserveAspectRatio="none"`; `src/app.js:813` independently normalizes longitude and latitude to percentages. The 390px view has a map container about 350px wide and 520px tall, so the geographic region is stretched vertically; screenshot `map-390.png` shows the result. Preserve a stable geographic projection/aspect ratio inside the viewport, letterbox if necessary, and let zoom/pan use that projection. Suggested: `$impeccable adapt`, `$impeccable layout`.

5. **[P2] The phone leaderboard conceals half its columns and fragments readable names.** At 320px the scroll wrapper is 278px wide while its table is 559px; at 390px it is 348px versus 559px. At 320, only Rank/Player/School/Pts are initially visible; Solved starts at x=300.45, Win=381.06, Attempt=434.97, Avg=526.14. The Player column is only 79.03px including 24px horizontal padding, leaving ≈55px for text. A valid 47-character fixture name creates a 165px-tall row; even “Player 2” wraps. `style.css:1183` applies `overflow-wrap:anywhere` to every table cell. Wrapper `index.html:201` has no explicit label, role, tabindex, or scroll hint; table headers have no caption explaining abbreviated metrics. At 768 and 1440 the whole table fits. Prefer a mobile ranking row with rank/name/points and expandable secondary metrics, or preserve usable name width and clearly signpost horizontal scrolling. Do not claim absence of page overflow means this table is usable. Suggested: `$impeccable adapt`, `$impeccable clarify`.

6. **[P2] Navigation communicates selection only through styling.** `src/app.js:303` toggles `.is-active` on Daily Puzzle / Past Puzzles / Leaderboard / Map without `aria-pressed`, `aria-current`, or a complete tab pattern. Browser confirmed all four buttons have null pressed/current state in both daily and leaderboard views. By contrast, leaderboard sort buttons explicitly get `aria-pressed` at `src/app.js:1082`. Add a consistent selected-state semantic model, plus a labeled navigation/group landmark. This is an accessibility/state-discoverability gap, not a claim that each button is inherently invalid HTML. Suggested: `$impeccable harden`.

7. **[P2] First-load assets are oversized for a lightweight daily game.** The logo is 605,527 bytes and 2250×2250 native pixels for 70px desktop and 108px mobile display (`index.html:42`, `style.css:68`, `style.css:1054`). `src/app.js:218` eagerly fetches 955,915-byte `data/puzzles.json` plus 220,658-byte `data/schools.json` before enabling play. Enabled account setup also loads the same-origin 218,252-byte SDK (`src/auth.js:8`, `src/auth.js:226`). File sizes are uncompressed source sizes, not measured production network transfers; the static server does not establish CDN compression/caching or Core Web Vitals. Resize/compress the logo and reserve its aspect ratio; separate the minimum current-puzzle/guessing index from the full archive/map data, then measure production loading. Suggested: `$impeccable optimize`.

8. **[P2] Essential support text is smaller/tighter than the surrounding interface.** `#score-status` measures 11.84px with 14.208px line-height at every width (`style.css:269`). It contains persistence and daily-only scope information. Desktop/tablet helper and status text is 13.12px/16.4px (`style.css:112`), while phone helper text improves to 14px/21px (`style.css:1150`). The desktop overlay independently flags tight line height / tiny body text. Establish a readable support-text floor around 14px and 1.4–1.5 line-height, especially for account persistence explanations. WCAG does not impose a universal minimum font size; this is a readability finding. Suggested: `$impeccable typeset`.

9. **[P3] Color/type choices are only partly centralized.** `style.css:1` provides CSP brand tokens, fonts, radii, and shadows, but translucent surfaces repeatedly embed `rgba(112,143,150,…)`/white/green values and sizing is spread through individual selectors; celebration colors are repeated at `src/app.js:584`. Use semantic surface/text/feedback/control tokens and a small support/label/body type scale to prevent future variants drifting. No dark-mode requirement is inferred. Suggested: `$impeccable document`, `$impeccable polish`.
